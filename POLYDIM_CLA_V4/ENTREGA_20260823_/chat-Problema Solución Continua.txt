🟠 HALLAZGO #18 (ALTO, verificado): log_map colapsa la distancia geodésica cerca del antípoda en vez de divergir a π
El Whitebook dice "distancia geodésica correcta". Probé puntos progresivamente más cerca del antípoda de x:

eps=1e-03  θ_real=3.140593  |log| medido = 3.1406   ✓ OK
eps=1e-05  θ_real=3.141583  |log| medido = 0.0702   ✗ debería ser ~3.1416
eps=1e-07  θ_real=3.141593  |log| medido = 0.0010   ✗ colapsa a ~0
eps=1e-09  θ_real=3.141593  |log| medido = 0.0007   ✗ colapsa a ~0
Causa raíz (confirmada paso a paso): dot_clipped = clip(dot, -1+1e-7, ...). Como dot = cos(π-eps) ≈ -1 + eps²/2, para eps < ~4.5e-4 el dot real ya es más extremo que el piso del clip, así que dot_clipped queda fijo en -1+1e-7 sin importar qué tan cerca esté realmente y del antípoda. Esto arma una "zona muerta" angular de radio ~4.5e-4 rad alrededor del antípoda donde log_map devuelve magnitudes chicas y básicamente aleatorias en vez de ~π. No tira NaN — es peor: da un número plausible pero silenciosamente falso. En D=10,000, con datos reales, pares casi-antipodales no son un caso exótico.

Fix verificado (reemplaza log_map completo, uso atan2(‖proj_y‖, dot) que evita la cancelación del arccos con clip):

python
@staticmethod
@jit
def log_map(x: jnp.ndarray, y: jnp.ndarray) -> jnp.ndarray:
    dot = jnp.clip(jnp.einsum('i,i->', x, y), -1.0, 1.0)
    proj_y = y - dot * x
    proj_norm = jnp.linalg.norm(proj_y)
    theta = jnp.arctan2(proj_norm, dot)          # robusto: sin(theta)=||proj_y|| exacto
    is_identity = proj_norm < 1e-9
    safe_norm = jnp.where(is_identity, 1.0, proj_norm)
    return jnp.where(is_identity, jnp.zeros_like(x), (theta / safe_norm) * proj_y)
Reverifiqué con este fix: sigue θ_real con error ~0 hasta eps=1e-9 (el límite real de precisión float64, no un bug — ahí sí es matemáticamente un punto de medida cero). Mejora de ~5 órdenes de magnitud en el radio de validez respecto al original.

python
@staticmethod
@jit
def grassmann_projector(x, V_k, eps: float = 1e-12):
    v_tx = jnp.einsum('dk,d->k', V_k, x)
    proj_v = jnp.einsum('dk,k->d', V_k, v_tx)
    star_x = x - proj_v
    norm = jnp.sqrt(jnp.einsum('i,i->', star_x, star_x))
    safe_norm = jnp.maximum(norm, eps)
    return jnp.where(norm < eps, jnp.zeros_like(x), star_x / safe_norm)
🟡 HALLAZGO #20 (MEDIO, verificado): SkewLowRankUpdate/CliffordRotors NO es la transformada de Cayley que dice el Whitebook
La sección 3.1 del Whitebook promete "Inversión exacta en SO(D)... factor 156,000×". El código real:

Medí la deriva de norma directamente:

input norm:  1.0
output norm: 1.0008628995951934   # drift = 0.086% en una sola aplicación
No es una rotación exacta — es una aproximación lineal que se sale de la esfera. CliffordRotors.apply_low_rank_rotor "tapa" esto renormalizando después, lo cual evita que la norma derive pero no garantiza ⟨Rx,Ry⟩=⟨x,y⟩ (la isometría real que se certifica es más débil de lo que dice la Whitebook).

Fix verificado: implementé el Cayley exacto vía Woodbury tal como lo promete la Sección 3.1 (O(r²D+r³)), y lo contrasté contra el cálculo denso D×D de referencia — coincide a precisión de máquina (diff=1.4e-16) y preserva norma exacta:

python
@staticmethod
@jit
def apply_cayley_exact(x, U, V):
    D, r = U.shape
    W = jnp.concatenate([U, V], axis=1)                  # D x 2r
    Ir, Zr = jnp.eye(r), jnp.zeros((r, r))
    K = jnp.block([[Zr, Ir], [-Ir, Zr]])                  # W K W^T = UV^T - VU^T = A
    Wt = W.T
    Wt_x = Wt @ x
    rhs = x + 0.5 * (W @ (K @ Wt_x))                      # (I + A/2) x
    M = -2.0 * K - (Wt @ W)                                # Woodbury: B^{-1} - W^T W, B=A/2, B^{-1}=-2K
    return rhs + W @ jnp.linalg.solve(M, Wt @ rhs)         # (I - A/2)^{-1} rhs
Esto reemplaza la aproximación en linear.py y clifford.py y cumple lo que el Whitebook ya afirma que existe.
